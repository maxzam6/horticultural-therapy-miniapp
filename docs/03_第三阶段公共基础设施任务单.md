# 第三阶段任务单：公共基础设施冻结

> 状态：已裁决，可直接执行  
> 前置条件：第二阶段“uni-app 源码工程初始化”已完成  
> 建议工期：2 个工作日  
> 参与者：开发者 A、开发者 B、项目负责人

## 1. 阶段目标

第三阶段只完成业务页面开发前的公共基础设施，目标是让后续 P01–P14 页面使用同一套视觉组件、路由、状态和数据接口。

完成本阶段后，后续页面开发不得再各自创建重复的按钮、卡片、数据字段、Storage Key 或 Mock 读取方式。

本阶段不实现具体业务页面，不接微信云开发，不开发后台、复杂登录或社区功能。

## 2. 阶段完成定义

第三阶段满足以下条件才算完成：

1. 全局视觉 Token 和基础组件 API 已冻结。
2. 14 个页面路由、5 个 Tab 和页面跳转方式已冻结。
3. 用户、评估、体验三个 Pinia Store 的公共状态和 Action 已冻结。
4. 页面只能通过 Data Adapter 获取业务数据，不能直接读取 Mock 文件。
5. 用户、10 道评估题、5 个课程、记录四类 Mock 数据结构已冻结。
6. 本地 Storage Key、读写和重置方式统一。
7. 新环境执行 `pnpm install` 和 `pnpm build:mp-weixin` 可以成功。
8. 两条开发分支分别通过 Review，合并后 `main` 保持可运行。

## 3. 明确不做

- 不完成 P01–P14 的正式视觉和业务内容。
- 不实现 10 题答题交互和评分公式。
- 不实现体验任务状态机和 Record 生成。
- 不接入微信真实登录、openid、云函数、云数据库或云存储。
- 不建设 Express、MySQL 或管理后台。
- 不制作社区内容流和社交功能。
- 不增加 PRD v1.2 以外的新功能。

## 4. 文件所有权

为避免两人修改同一批公共文件，第三阶段按以下方式冻结所有权。

| 文件范围 | 负责人 | 规则 |
|---|---|---|
| `src/styles/**` | 开发者 A | B 不直接修改 |
| `src/components/**` | 开发者 A | 组件 API 变更需通知 B |
| `src/pages.json` | 开发者 A | 路由增删须项目负责人确认 |
| `src/App.vue` | 开发者 A | 只保留全局样式和生命周期入口 |
| `src/mock/**` | 开发者 B | A 不直接修改 Mock 字段 |
| `src/stores/**` | 开发者 B | Store Action 变更需通知 A |
| `src/services/**` | 开发者 B | 页面统一经 Adapter 调用 |
| `src/config/routes.js` | 开发者 B | 路由值必须与 `pages.json` 一致 |
| `src/main.js` | 开发者 B | 负责 Pinia 和全局插件注册 |
| `package.json` / 锁文件 | 开发者 B | 新依赖须先说明用途 |
| `README.md` / 本任务单 | 共同 Review | 由任务负责人统一合入 |

禁止为了赶进度复制同名组件、临时字段或另一套数据读取逻辑。

## 5. 开发者 A 任务

分支：`feat/experience-ui`

### T3-A01 全局视觉 Token 冻结

交付文件：

- `src/styles/tokens.scss`
- `src/styles/global.scss`
- `src/uni.scss`

必须统一：

- 主色、深绿、浅绿、背景、Surface、暖色点缀。
- 正文、次级文字、弱文字、边框颜色。
- 页面左右边距。
- 8/16/24/32/48/64rpx 间距节奏。
- 按钮、普通卡片和大卡片圆角。
- 统一轻阴影。
- 状态栏和底部安全区处理。

验收：

- 页面文件不再新增私有主色。
- Token 与 PRD v1.2 的 UI 规范一致。
- 不出现医疗蓝白、后台管理或科技大屏风格。

### T3-A02 公共组件冻结

在现有 `AppPageShell` 基础上完成以下公共能力：

| 组件 | 最小能力 |
|---|---|
| `AppPageShell` | 页面边距、安全区、标题区域、默认背景 |
| `AppButton` | primary/secondary、disabled、loading、点击态 |
| `AppCard` | 默认卡片、可点击态、统一圆角和阴影 |
| `AppSectionHeader` | 标题、说明、可选右侧操作 |
| `AppStateView` | loading、empty、error 三态及可选重试 |
| `AppProgress` | 0–100 进度展示，不承载业务计算 |

验收：

- 组件只负责表现和通用交互，不写评估、课程或记录业务逻辑。
- Props、Emits 和默认值清晰。
- 组件能在微信小程序构建中通过。
- 不引入新的 UI 框架。

### T3-A03 路由与 Tab 基线

任务：

- 核对 `pages.json` 的 14 个页面路径与 PRD 一致。
- 固定原生 TabBar，不开发 custom TabBar。
- 固定首页、探索、记录、社区、我的五个 Tab 顺序。
- 检查普通页面使用 `navigateTo`，Tab 页面使用 `switchTab`。
- 确认页面容器不会被状态栏或底部安全区遮挡。

阶段内允许保持文字 Tab，图标统一放到后续视觉打磨任务，不阻塞公共结构冻结。

验收：五个 Tab 可切换，14 个页面均能编译，不出现不存在路由。

## 6. 开发者 B 任务

分支：`feat/assessment-data`

### T3-B01 Store 公共契约冻结

#### userStore

状态：

```text
user
isAuthenticated
loading
error
```

Action：

```text
loadCurrentUser()
startMockSession()
saveProfile(profile)
resetUser()
```

#### assessmentStore

状态：

```text
questions
answers
currentIndex
result
submissionStatus
error
```

Action：

```text
loadQuestions()
setAnswer(questionCode, value)
goPrevious()
goNext()
setResult(result)
resetAssessment()
```

本阶段只冻结状态和 Action，不实现评分公式。

#### experienceStore

状态：

```text
courses
activeCourseId
activeSession
records
loading
error
```

Action：

```text
loadCourses()
selectCourse(courseId)
setActiveSession(session)
loadRecords()
addRecord(record)
resetExperience()
```

验收：页面不自行维护与 Store 重复的全局业务状态。

### T3-B02 Data Adapter 契约冻结

页面只调用 Adapter，不判断数据来自 Mock 还是云开发。

冻结接口：

```text
getCurrentUser()
mockLogin()
saveUserProfile(profile)
getAssessmentQuestions()
saveAssessmentSubmission(payload)
getLatestAssessment()
getCourses()
getCourseById(courseId)
startExperienceSession(courseId)
completeExperienceSession(sessionId, payload)
getRecords()
getRecordById(recordId)
```

阶段要求：

- 完成 Mock 实现或返回明确的初始化数据。
- 页面不得直接 `import '@/mock'`。
- Real Adapter 只保留入口，不连接云开发。
- 返回值字段使用 PRD v1.2 命名。
- 新代码不得使用 `balanceIndex`，统一使用 `experienceOverviewScore`。

### T3-B03 本地存储封装

新增统一 Storage Service，禁止页面散落 `uni.setStorageSync`。

固定 Key：

```text
horticulture:user
horticulture:assessment-draft
horticulture:latest-assessment
horticulture:active-session
horticulture:records
```

最小方法：

```text
getStorage(key, fallback)
setStorage(key, value)
removeStorage(key)
clearDemoStorage()
```

验收：

- JSON 读取失败时返回 fallback，不导致页面崩溃。
- `clearDemoStorage()` 只清理本项目 Key，不调用全局清空全部微信缓存。

### T3-B04 Mock 数据校验

检查并冻结：

- 用户对象 1 份。
- 状态探索题恰好 10 题。
- 维度只能是 `emotion`、`stress`、`nature`。
- 题目 code 唯一。
- 五感课程恰好 5 条，courseId 唯一。
- 多肉课程 ID 固定为 `course-succulent`。
- 示例 Record 包含唯一 `id`、`courseId`、`completedAt`；页面路由通过参数名 `recordId` 传递该 `id`。

增加可执行校验命令：

```bash
pnpm check:mock
```

该命令只校验结构，不校验专业内容和评分科学性。
