# 社区、日常记录与后台：运行及验收说明

更新：2026-09-15。执行方式：主对话统一实现，独立子代理只读 Review，不再分 A/B 阶段交接。

## 1. 当前完成到哪里

已完成可本地运行的业务实现、云函数入口、后台及自动化联调。**尚未部署到真实微信云环境，不能宣称已上线或真实双手机互通已通过。** 原有第六阶段以后主链与此次新增云功能的验证范围不同，不能沿用旧真机结论代替新功能验收。

已实现：

- 保留首页、首次档案/评估、再次探索、体验任务、自然印记、记录和我的主链；共 17 个页面、5 个 Tab。
- 记录页增加“＋”：日常照片日记，1–3 张图片、标题和正文，默认仅自己可见，可编辑、删除。
- 体验记录及日常日记均可明确选择同步社区、查看状态、取消公开。评估分数、年龄等档案信息不随社区发布。
- 社区自然风格双列图文列表、详情、点赞、单层评论；没有私聊和关注。
- <=30 名启用成员的审批和限制；待审核/限制/停用状态均在服务器校验。
- 独立网页后台：课程草稿、图片、步骤、发布、下架、归档、默认推荐；更新课程不改变已开始体验的历史版本。
- 后台官方帖子、手工每周精选、置顶、官方评论、审核及下架、成员管理、管理员角色和操作审计。
- 社区内容目前采用人工审核后公开；不是已接通平台自动内容安全接口。

没有自动发布每周精选的定时任务；管理员手工选择仍公开的作品。作品撤回后精选不继续暴露其内容。

## 2. 三种运行模式

| 模式 | 用途 | 身份与数据 |
| --- | --- | --- |
| `mock`（默认） | 原离线答辩演示 | 原本地数据，不连接社区 |
| `local` | 本机多账号与后台联调 | 回环 HTTP 服务、临时测试账号、本机文件持久化 |
| `cloud` | 待部署的真实小程序和后台 | 微信 OPENID / CloudBase 管理员 UID、云函数、云数据库和私有云存储 |

在云模式中，社区日记/帖子/评论/课程在云端；私人档案、评估、体验 Session 与原始体验 Record 仍按当前用户隔离保存在本机。只有明确选择公开的体验字段上传云端。**本次不提供全部私人历史跨设备同步，也不自动把旧 Mock 数据归属给真实微信用户。**

## 3. 现在怎么启动本地联调

在仓库根目录使用 Node.js 20–24，安装锁定依赖：

```powershell
corepack pnpm install --offline
```

新电脑没有缓存时改用 `corepack pnpm install --frozen-lockfile`。分别打开三个终端，保持运行：

```powershell
corepack pnpm local:server
```

```powershell
corepack pnpm local:mini
```

```powershell
corepack pnpm local:admin
```

- 浏览器小程序联调入口：`http://127.0.0.1:5173`。
- 管理后台：`http://127.0.0.1:5174`。
- 服务端绑定 `127.0.0.1:8788`，不对外网开放。
- 服务端终端打印临时本地密码；后台账号 `admin`，小程序测试账号 `member-a`、`member-b`。这不是正式管理员账号。
- 两名用户使用不同浏览器配置/无痕窗口，避免共享同一浏览器本地存储。
- 本地数据在 `.local-community/`，图片不通过公共静态目录提供；此目录已忽略，不提交 Git。
- 重启服务会更换默认临时密码、使旧会话失效，测试数据保留。重新登录即可；不要因此清空用户资料。

浏览器联调入口不是可扫码上线的小程序，也不能把这个本地服务直接部署成正式后台。

## 6. 云部署还需要哪些条件

项目负责人提供或在本机配置真实云环境 ID；确认 AppID 关联、部署权限、CloudBase 管理员登录方式和初始管理员 UID。不要在对话或 Git 提交密码、SecretId、SecretKey。

部署清单（目前未执行）：

1. 创建/确认微信云开发环境，关联项目现有 AppID；保留负责人本地 `src/manifest.json` 配置。
2. 新建空集合 `garden_state`，客户端直接读取和写入均拒绝。云存储同样拒绝客户端直接读写，由已授权云函数代理。
3. 在 `cloudfunctions/garden-api` 执行 `npm ci`，按平台支持的 Node.js 运行时部署名为 `garden-api` 的云函数；建议先验证 Node.js 20 是否可选。不把本地测试服务部署上去。
4. 在 CloudBase 配置后台账号密码身份提供方，建立真实管理账号并获取认证 UID，不是自填昵称或客户端角色。
5. 设置 `$env:GARDEN_ADMIN_UID='实际认证UID'`，在仓库根执行 `corepack pnpm cloud:seed`，生成 `dist/cloud/garden_state.json`（JSON Lines）。**只导入新建空集合，不能覆盖已有业务集合。**
6. 本地 `.env.local` 设置 `VITE_DATA_MODE=cloud`、`VITE_CLOUD_ENV=实际环境ID`、`VITE_RESET_DEMO_ON_LAUNCH=false`。执行 `corepack pnpm build:mp-weixin:cloud` 和 `corepack pnpm build:admin`；前者会把云函数复制到导入目录并写入 `cloudfunctionRoot`。云模式不允许自动清空演示数据。
7. 上传小程序构建产物 `dist/build/mp-weixin`；后台 `dist/admin` 部署到受控 HTTPS 站点，配置该域名的云访问与身份认证安全域名。不要启用匿名管理权限。
8. 初次微信用户进入为待批准成员，由管理员审批；两台真机完成发布→审核→互相可见→点赞/评论→撤回全流程，再验收禁用成员和越权拒绝。
9. 正式提供用户使用前，确认平台内容安全接入要求与项目隐私告知、照片使用授权、人工审核责任人。当前只能确认代码提供了人工审核门禁，不能宣称平台审核已经通过。

## 7. 与前期契约的实现对应

产品规则沿用 v1.3；以下是实际落地差异，替代旧任务单中“待实现”的描述：

- 原契约中的用户、课程、日记、帖子等是逻辑实体；物理数据库使用一个 `garden_state` 集合，**每实体一个文档**，另有版本 manifest。不是把所有数据塞进一个文档。
- 云仓库在事务外读取一致性快照，事务内检查 manifest 版本并只写变更文档，冲突重试；大规模历史数据性能尚未实云验证。
- 实际 RPC 名称及字段以 `cloudfunctions/garden-api/domain.cjs` 的 action、`src/services/community-api.js` 和 `admin/api.js` 为对照。常用入口为 `identity.*`、`journals.*`、`shares.*`、`posts.*`、`comments.*`、`admin.*`。没有另建 Express/MySQL。
- 课程包含不可变版本；Session 保留开始时课程快照，版本图片继续被保护。成长统计不把日常日记计算成课程完成次数。
- 上传原图上限 5MB，客户端压缩后通过云函数上传，服务器校验 JPEG/PNG/WebP 文件签名；不接收任意公开图片 URL。小程序将授权后的图片保存到专用本地缓存用于显示，启动清理仅匹配本项目缓存前缀。
- 所有发布先进入人工审核；官方身份由服务器管理员权限决定，不接受客户端伪造角色。
- 超级管理员有“清理未引用图片”操作：每批至多 10 张、超过 24 小时且无引用才可清理，先标记再删除。当前不是自动定时清理；历史课程版本图片不会因此被删除。
- 备份必须同时包含整个数据库集合及对应云文件；先恢复到独立测试环境验证。不能只恢复 manifest 或只恢复图片。

官方技术参考：[CloudBase 事务](https://docs.cloudbase.net/database/transaction)、[服务端认证上下文](https://docs.cloudbase.net/en/api-reference/server/node-sdk/auth)。上线配置仍需以实际账号控制台可用能力核实。
