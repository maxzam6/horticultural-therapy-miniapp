# 园艺疗法小程序 PRD v1.3：社区与后台增量修订

> 日期：2026-09-14。状态：已确认需求的开发规格；功能尚未实现。
> 代码审查基线：`main @ 63b77b9`。本轮为文档交付，不代表云服务已经开通。
> 本文与 [v1.2 合订版](园艺疗法小程序_PRD合订版_v1.2.md) 共同构成当前 PRD。本文明确替换的条款优先，其余沿用 v1.2；无需重新复制或删除原合订版。

## 1. 背景与变更依据

保持护理学院大创、非商业化、园艺疗法数字化体验展示的定位。专业课程、官方点评及精选文字由甲方提供或审核，技术团队负责实现。

甲方及项目负责人已确认：使用人数 30 人以内；真实多人社区；点赞和评论，无私聊；记录页增加 `+` 创建日常记录；所有体验记录和日常记录可主动同步到社区；使用微信云开发；独立网页后台，管理员账号密码登录，初期 1–3 名管理员；后台管理课程和社区，支持官方发帖、每周精选和官方评论。

本轮确定的实施默认值：日记 1–3 张图片，标题 1–40 个字符，正文 1–1000 个字符；评论 1–300 个字符；单层评论；成员审批加入；每页加载 20 条。它们用于形成可执行规格，可在实现前由项目负责人调整，不宣称是甲方逐字指定。

### 1.1 被替换的旧条款

| 旧条款 | v1.3 适用规则 |
|---|---|
| 社区仅占位，禁止发帖/点赞/评论 | 本阶段必须实现真实发布、点赞、评论、官方互动 |
| 用户不足 10 人 | 项目使用规模 30 人以内；云端最多 30 个已批准小程序成员 |
| 不做后台和上传 | 实现独立管理后台、受权限控制的云端图片上传 |
| 固定 14 页面，不能增加路由 | 保留原 14 路由及 5 个 Tab，按页面手册新增 3 个非 Tab 页面 |
| 课程直接取 Mock | 普通展示构建仍支持 Mock；云端构建读取后台发布的课程版本 |
| 所有业务仅本地 | 测评/既有体验记录继续本地；云端承载身份、课程、日记、社区及后台 |

历史阶段的完成与冻结证据不改写。新阶段扩展这些边界，不能以历史文档禁止项拒绝实现已确认功能，也不能据此重做测评或扩大商业化范围。

## 2. 必须完成与排除范围

必须完成：真实成员身份、课程云端化、课程后台、日记拍照/相册上传、两类记录同步、双列社区、帖子详情、点赞及取消点赞、单层评论及本人删除、官方发帖与官方评论、精选引用、置顶、后台治理、操作记录、权限与内容审核。

不包含：私聊、关注、评论嵌套回复、商业广告、支付、排行榜、推荐算法、自动每周生成/定时发布、用户画像、测评或成长算法升级。每周精选由管理员手动制作发布。

## 3. 成员与管理员

- 小程序微信身份由服务端确认，禁止使用 `demo-user-001` 或客户端提交的用户 ID 作为云端凭据。
- 初次访问云端社区，成员状态为待批准；管理员批准后才能浏览成员社区、上传和互动。等待状态不阻塞本地核心体验。
- 最多 30 个已批准成员，并发批准必须在云端原子控制；管理员网页账号单独计数。如管理员也作为小程序成员，则占成员名额。
- 成员状态分为待批准、正常、禁止发布、停用。禁止发布者可浏览、取消自己的点赞、删除自己的内容，但不能新增帖子、点赞或评论；停用者不能进入社区。
- 网页后台使用受托管认证保护的管理员账号密码，不自建明文密码表；账号对应服务端管理员授权。
- 第一版使用内容管理员、超级管理员两个后台权限集合。内容管理员负责官方内容与社区治理；超级管理员还可管理课程、成员和管理员。初期可将指定的 1–3 名管理员授予超级管理员，不能因此取消服务端权限判断。
- 正式资料归真实云端身份；云端改昵称不能顺带设置“已完成自然档案”。本地昵称与云端显示名衔接由用户保存操作完成，不能把默认演示昵称反复覆盖到云端。

## 4. 记录页与日常记录

记录页保留原成长汇总，新增 `+` 入口和“全部 / 体验记录 / 日常记录”筛选。两类记录按记录时间倒序显示，卡片标注类型和社区发布状态。

日记编辑支持拍照、相册、预览、移除图片、标题、正文、保存和取消；保存前校验必填与长度。照片先压缩再上传，单张压缩后上限 5 MB，云端也校验数量、大小与格式。不强制读取定位。

日记保存到云端私人区域，界面明确“保存到我的记录，仅自己可见”。上传失败可重试；记录未成功保存不得提示成功。取消编辑不改变既有内容，新上传的无引用文件进入清理队列。

日记详情可编辑、删除并选择同步。日记不加入 `experienceStore.records`，不计入完成次数、累计分钟、感官数或成长等级。记录页展示合并列表，统计继续只读体验记录集合。

无网时本地体验记录仍可查看；日记云端区域显示失败与重试，不能把云端获取失败显示成“从未有记录”。

## 5. 所有记录同步社区

“所有记录”指记录页中的体验记录和日常记录，不包含问卷答案、测评报告、年龄等用户档案。

- 新记录默认不发布。每条记录可在详情与记录卡菜单开启“同步上传社区”，已有历史体验记录也支持。
- 发布前预览具体图片和文字，提示“发布后其他已批准成员可见”；只发送预览字段。
- 体验记录分享字段：课程标题、感官、心情、感受、图片；不公开测评分数、年龄、OpenID、原始用户 ID。它仍属于成员分享，不标记为官方验证的完成凭证。
- 本地历史记录只能在当前设备用户主动选取并确认后上传分享副本，不批量自动迁移，也不把演示记录当成该微信身份的真实历史。
- 一条原记录始终关联至多一个社区帖子；重复点击、超时重试、取消后再次发布不得重复建帖。
- 开启同步后先显示“审核中”，审核通过才可见；失败或被拒绝不影响私人记录保存。
- 日记编辑后如已开启同步，原公开版本立即暂时隐藏，新版本审核通过后恢复；不保留公开旧内容与私人新内容不同步的模糊状态。
- 取消同步立即撤下帖子并保留个人记录；删除个人记录同时撤下对应帖子。云端失败时保持“处理中/待重试”，不可显示“已全部删除”。
- 第一次发布后的帖子 ID 保持不变，取消再发布沿用原互动；被作者最终删除则不可恢复。
- 管理员隐藏内容不能被作者自行开关同步绕过；必须经管理员解除隐藏限制。
- 精选只引用已公开作品。原作取消同步、隐藏或删除后，精选中的对应引用立即不可见；不保留脱离原作控制的图片副本。

## 6. 多人社区

沿用 5 个底部 Tab。社区为双列瀑布流，保持米白、自然绿、圆角卡片；图片显示比例、两行标题、作者昵称、官方标识、点赞数和评论数。无图的体验分享使用本地植物封面，不能出现破图。

排序：置顶帖子优先，再按发布时间倒序；同时间按 ID 确定顺序。采用稳定游标分页、下拉刷新和加载更多；未发布、审核中、隐藏内容不得泄露到列表、详情或图片接口。

帖子详情展示全文与图集、官方/成员身份、点赞和评论。点赞采用目标状态提交，每个成员每帖一赞，可取消，连续点击和网络重试不累加。评论为单层文本，评论审核通过才计数，作者可删除自己的评论；第一版不做评论编辑与回复套回复。

点赞/评论中的身份、数量和官方标识均由云端裁定。后台隐藏或删除帖子后，帖子下所有互动停止对成员展示；不能继续新点赞或评论。

## 7. 官方运营与每周精选

后台可独立创建官方帖子，无需先创建个人记录；支持草稿、图文、预览、发布、编辑、下架、置顶。社区显示“园艺疗法项目组 · 官方”，普通成员无法伪造。

后台在成员帖子下可发表、编辑、删除官方评论；页面明确标记官方。对外显示统一项目组身份，后台保留实际管理员身份和操作时间。

每周精选作为一种官方帖子，管理员手动选择仍公开的成员作品、写导语和点评，保留原作者昵称及原帖入口。发布确认中说明：公开作品可在本社区精选中被引用，撤回分享会同时移除引用。不能选私密记录；需要重新上传/脱离原帖复用的内容不在第一版范围内。

官方发帖和评论同样经过内容审核，审核失败不能强制公开。后台负责反馈和引导，专业文字由甲方负责，不自动生成医疗结论。

## 8. 课程资源管理

后台支持课程列表、感官分类、封面、标题/副标题/介绍、时长、材料、步骤图文、正念提示、安全事项、预览、排序、发布和下架。

保留五类感官及 `course-succulent` 固定课程标识。首次部署导入现有课程，步骤不完整的课程只作准备中展示，不允许开始任务；多肉完整版本为上线门槛。

课程采用草稿与已发布版本分离。保存草稿不改变线上课；发布生成不可变版本。用户开始体验时固定课程版本，进行中的任务和历史印记不随后台修改变化。

被引用课程只允许归档/下架，不能删除历史版本。下架后不能新开始体验，已开始体验仍按原快照完成。

后台可设置默认推荐，必须指向已发布且步骤完整课程；测评返回的推荐课程不可用时采用此默认项。第一版默认多肉，感官分类结构和评分公式保持。

## 9. 管理后台与数据边界

独立电脑网页后台，课程管理、帖子/评论治理、官方发布、成员与管理员管理、操作日志。界面以清晰表单和预览为主，不做统计大屏。

管理员可管理已公开或已提交审核的社区内容；无普通后台入口批量浏览私人日记或测评。数据库运维账号属于另行管控的高权限账号，不与内容管理员账号混用。

课程及社区写操作通过服务端校验身份。管理操作保留操作者、对象、动作、理由、时间；日志不复制完整私人正文和图片。

## 10. 数据与演示模式的关系

- 原 `VITE_DATA_MODE=mock` 模式保留为离线主链演示。
- 新增明确的云端混合模式：真实身份、课程、日记和社区来自云端；测评与体验进度保持本机，按真实身份隔离本地数据。
- 禁止直接把当前 `realAdapter` 占位开关打开作为“已接入云端”。
- 云端不可用不得悄悄退回假帖子、假点赞或假用户成功结果。
- 云端构建禁止启用每次启动清空本地状态；独立新用户演示构建仅适用于 Mock，不清理云数据库，也不能冒充新微信身份。
- 普通演示模式此前有一条 Mock 示例记录，清本地状态后仍会回退该示例；这不是云端用户历史。

## 11. 验收主线

原主线继续两遍通过：P01→P13，首次测评、返回幂等、档案恢复、体验记录和成长统计正确。

新增主线：成员甲登录 → 批准 → `记录 +` → 拍照写日记 → 私密保存 → 同步 → 审核 → 成员乙看到同一帖子 → 点赞 → 评论 → 官方回复 → 制作精选 → 原作者撤回 → 原帖与精选引用均不再展示。

后台课程主线：编辑草稿 → 预览 → 发布 → 小程序新体验读取新版 → 已开始旧体验仍可完成 → 下架阻止新开始。

验收需要云端真实证据，至少两台设备/两个微信账号和管理员账号；30 个成员边界及越权请求用服务端测试验证，不要求 30 人同时到场。构建通过不等同多人验收通过。
