# 第七阶段任务单：答辩交付与体验版准备

> 状态：active（开发者 A / B 可按本任务单开工）
> 产品依据：《园艺疗法小程序_PRD合订版_v1.2.md》
> 业务开工基线：`main @ ebf8935`
> 阶段目标：不增加功能，将已完成的 P01–P14 稳定交付为可扫码、可演示、可兜底的微信体验版

## 1. 阶段唯一目标

本阶段只做答辩交付：

```text
冻结 Mock 演示基线
→ 全局视觉与文案终检
→ 构建与配置审查
→ 双机真机验收
→ 上传微信体验版并验证二维码
→ 连续完整演练 3 次
→ 最终交付冻结
```

唯一答辩路径保持不变：

```text
扫码进入 → 首页 → 开始体验 → 自然档案 → 状态探索 → 状态报告
→ 五感花园 → 多肉种植体验 → 体验任务 → 自然印记 → 记录 → 我的
```

社区只在问答环节作为未来方向占位展示，不插入上述 3–5 分钟主路径。

## 2. 本阶段发布模式

### 2.1 默认数据模式

- 答辩体验版固定使用 `VITE_DATA_MODE=mock`。
- Mock 模式必须支持全部 P01–P14 页面和完整主路径。
- 不依赖云函数、云数据库、云存储或外部 API。
- 断网或网络波动不得破坏已经打开的小程序主流程。
- 不修改评分、Session、Record、成长汇总或路由契约。

PRD 旧章节中的 `VITE_USE_MOCK` 属于历史写法；当前源码唯一有效开关是 `VITE_DATA_MODE`。

### 2.2 AppID 与账号边界

- 项目负责人上传电脑已在 `src/manifest.json` 本地配置 AppID。
- 该本地修改属于项目负责人的上传配置，本任务发布提交不覆盖、不暂存。
- AppID 是否提交仓库需项目负责人另行明确；本阶段默认不提交。
- appSecret、云环境密钥、数据库密码和任何账号凭据禁止写入仓库、任务反馈或截图。
- “上传体验版、添加体验成员、生成二维码”属于外部账号操作，执行时必须由项目负责人操作或当场明确授权。

### 2.3 B050 阶段外保留项

既有 B050“页面稳定后的微信云开发接入”保持 `planned`，本阶段不启动。

不实现：

- 真实微信 openid 登录。
- 云函数、云数据库和云存储。
- Real Adapter 业务方法。
- 跨设备真实数据同步。
- 真实图片上传。

以后确需真实数据时，B050 必须另开阶段、单独评审，并保持 Mock 兜底。

## 3. 本阶段明确不做

- 不新增页面、路由、Tab 或产品功能。
- 不扩展社区、课程、评估、成长体系或用户系统。
- 不开发后台、Express、MySQL、管理端或科研数据看板。
- 不实现 dev-only 快速答题、跳页按钮或答辩捷径。
- 不为“看起来高级”增加复杂动画、音频、视频或上传。
- 不升级 uni-app、Vue、Pinia、Sass、Node 约束或其他依赖。
- 不因为甲方素材未到位而临时撰写专业疗效、安全、禁忌或可食用结论。
- 不把 `dist/`、`project.private.config.json`、本地 `.env`、二维码或账号信息提交仓库。


- 本阶段原则上以 Review 和验收为主；只有可复现的页面、路由、崩溃、内容或发布阻塞问题才允许改源码。

## 6. C014 发布基线与演示数据冻结

### 6.1 演示数据口径

- 用户：使用 Mock 登录，昵称和自然档案可现场填写并恢复。
- 评估：沿用现有 10 题和评分公式，不为了得到固定分数改答案或公式。
- 课程：五类课程卡完整，多肉种植是唯一完整演示课程。
- Record：至少保留一条可展示历史记录；现场完成的新 Record 必须位于 P12 首项。
- 成长汇总：继续从 Record 实时聚合，不写死展示数字。
- 社区：只显示“自然分享空间，未来开放”。

每次正式演练前记录起始状态：

```text
用户档案是否存在：
最近评估是否存在：
Record 数量：
成长汇总：
当前是否存在 active Session：
```

不得在答辩现场依赖手动修改 Storage。若需要全新用户演示，由项目负责人在演练前通过微信开发者工具清理本地 Storage，并重新完整走一遍主路径。

### 6.2 用户可见内容清理

用户界面和课程描述不得出现：

- `Mock`、`P01`–`P14`、任务 ID。
- “骨架”“待开发”“开发中”“待甲方确认”。
- 内部路由、Storage Key、字段名或构建状态。
- 医学诊断、正式量表或疗效承诺。

专业内容尚未定稿时，使用中性表达，例如“体验内容示例，专业内容以项目组最终确认为准”，不得暴露工程术语“Mock”。

### A071 全局视觉与文案终检

负责人：开发者 A。

当前状态：completed。A 侧提交：`13b7d12`；等价修复已集成至 `main @ ee57b32`。

Review 范围：

- S 级：首页、状态报告、五感花园、自然印记。
- A 级：体验详情、记录、我的。
- 主路径其他页面的安全区、按钮、卡片、字体和返回操作。
- P14 只做 C 级一致性检查。

必须检查：

- 主标题、正文和按钮无截断、溢出或遮挡。
- 底部 Tab、安全区和长页面滚动正常。

- 无用户可见工程术语、内部编号或调试状态。

只在发现可复现问题时修改对应页面；每个修改必须附页面、现象和修复前后验证结果。

### B051 构建与发布工程审查

负责人：开发者 B。

当前状态：completed。完成提交：`3ead1d4`，已合入 `main`。

交付：

- 新增 `scripts/check-demo.mjs` 和 `pnpm check:demo`，不新增依赖。

### C007 双机真机验收

负责人：A、B 分别执行，项目负责人汇总。

统一基线要求：

- 两侧使用同一个最终 `main` 提交。
- 至少一台主演示手机和一台备用手机；设备型号与微信版本记录在反馈中。
- 两台设备均从扫码或体验成员入口启动，不使用页面直达调试。

两台设备分别验证：

1. P01→P13 完整主路径。
2. P14 Tab 冒烟。
3. 返回、Tab 切换、重复点击和重启恢复。
4. 新 Record 出现在 P12 首项，P11/P12 `recordId` 一致。
5. P12/P13 成长汇总一致。
6. 无明显布局错位、破图、白屏、崩溃或业务 console error。

网络兜底验证：小程序已打开后切换弱网或断网，Mock 主路径仍可继续；恢复网络后无需改数据。

### C015 体验版上传与二维码验证

负责人：项目负责人执行账号操作，A/B 配合构建与验证。

执行前必须由项目负责人确认：

- 上传所用 AppID 与小程序账号正确。
- 上传版本号和项目备注。
- 体验成员名单。
- 当前 `main` 提交与工作区状态。

上传要求：

- 使用 `dist/build/mp-weixin` 本地构建产物。
- 不启用云开发，不填写 appSecret。
- 上传成功后记录版本号、上传时间和对应 Git 提交。
- 生成体验版二维码或体验成员入口。
- 主、备用设备均能进入正确版本。
- 二维码仅在项目团队与答辩范围内流转，不提交公开仓库。

### C008 连续完整演练 3 次

负责人：项目负责人主讲，A/B 交叉观察。

必须使用第 C015 的正式体验版执行：

| 遍次 | 设备/状态 | 重点 |
|---|---|---|
| 第 1 遍 | 主演示手机，正常网络 | 按 3–5 分钟讲解脚本完整走通 |
| 第 2 遍 | 主演示手机，已有档案与历史记录 | 验证恢复、Record 增量和重复点击保护 |
| 第 3 遍 | 备用手机或另一体验成员 | 验证扫码、首次进入与设备适配 |

每遍记录：开始/结束时间、是否通过、阻塞问题、非阻塞提示、Record 与成长汇总结果。

三遍中任一遍出现白屏、崩溃、主路径阻塞、数据断链或错误版本，C008 不通过；修复后必须从第 1 遍重新计数。

### C016 最终交付冻结

负责人：项目负责人。

冻结内容：

- 最终 `main` 提交。
- 七项既有检查与 `check:demo` 结果。
- 微信体验版版本号与对应 Git 提交。
- 两台设备验收结果。
- 三遍完整演练记录。
- 已知非阻塞提示和现场兜底方案。
- 3–5 分钟答辩操作与讲解顺序。

冻结后只允许修复页面错位、路由、崩溃和内容错误；禁止增加功能或升级依赖。是否创建 Git tag 由项目负责人在冻结时另行确认。
