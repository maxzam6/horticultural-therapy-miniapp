# 两人合作开发任务交互时序图

> 本图描述开发者 A、开发者 B 在两人协作中的任务交付、数据契约冻结、页面联调和验收顺序。它不是产品用户流程图。

## 1. 第一周协作时序

```mermaid
sequenceDiagram
    autonumber
    participant O as 项目负责人
    participant A as 开发者 A（页面与视觉）
    participant B as 开发者 B（数据与逻辑）
    participant R as 共享仓库 main
    participant D as 微信开发者工具/真机

    O->>A: 下发 PRD v1.2 与开发协作包
    O->>B: 下发 PRD v1.2 与开发协作包
    A->>B: 确认页面、路由、组件需求
    B->>A: 提交用户/评估/课程/记录字段草案
    A->>B: 确认页面所需字段完整
    A->>R: 合入项目骨架、TabBar、UI Token
    B->>R: 合入 Mock Adapter、Store、数据契约
    R->>D: 启动项目并验证五 Tab

    par 入口页面开发
        A->>R: 开发 P01、P02、P03
    and 评估模块开发
        B->>R: 开发 P04、P05、评分 Service
    end

    A->>B: 交付自然档案字段与保存交互
    B->>A: 交付评估结果对象
    Note over A,B: 冻结 emotion、stress、nature、experienceOverviewScore

    par 后半页面开发
        A->>R: 开发 P07、P08
    and 报告逻辑开发
        B->>R: 开发 P06 数据与推荐规则
    end

    A->>R: 按统一视觉完成 P06 页面样式
    B->>R: 补充状态恢复、异常提示、防重复提交
    R->>D: 联调 首页→五感花园
    D-->>A: 返回页面与真机适配问题
    D-->>B: 返回数据与状态问题
    A->>R: 修复视觉/路由问题
    B->>R: 修复状态/评分问题
    R->>D: 完整主链复测两遍
    D-->>O: 第一周 Demo 可运行
```

## 2. 第二阶段核心闭环时序

```mermaid
sequenceDiagram
    autonumber
    participant A as 开发者 A（页面与视觉）
    participant B as 开发者 B（数据与逻辑）
    participant R as 共享仓库 main
    participant D as Demo 验收环境

    A->>R: 开发 P09 多肉体验详情
    A->>B: 交付 courseId、steps、materials 使用方式
    B->>R: 开发 P10 体验 Session 与反馈
    B->>A: 完成体验后返回唯一 recordId
    Note over A,B: 禁止 P11 重新生成另一条记录
    A->>R: 开发 P11 自然印记并按 recordId 读取
    B->>R: 开发 P12 记录列表和印记详情读取
    A->>R: 开发 P13 我的及记录入口
    B->>R: 开发 P14 社区静态占位
    R->>D: 联调 多肉详情→任务→印记→记录→我的
    D-->>A: 返回视觉和导航问题
    D-->>B: 返回记录断链或重复提交问题
    A->>R: 修复页面一致性和 CTA
    B->>R: 修复 Record、Store 和持久化
    R->>D: 唯一答辩流程连续运行三遍
```

## 3. 单个任务交接时序

```mermaid
sequenceDiagram
    autonumber
    participant U as 上游开发者
    participant R as 功能分支/共享仓库
    participant V as 下游开发者/Reviewer
    participant M as main

    U->>R: 提交实现与自测说明
    U->>V: 发送任务 ID、运行入口、数据契约、已知问题
    V->>R: 拉取并运行
    V->>R: 按 PRD 路径走查
    alt 验收不通过
        V-->>U: 返回可复现问题和期望结果
        U->>R: 修复并补充自测
        V->>R: 再次验证
    else 验收通过
        V-->>U: 确认交接完成
        R->>M: 合并到 main
        M->>M: 验证答辩主链仍可运行
    end
```

## 5. 冲突处理顺序

发生文档、页面或排期冲突时，按以下顺序裁决：

```text
产品边界
↓
页面定义
↓
开发计划
```

- 产品定义以 PRD v1.2 中的 `01 产品需求规格说明书` 为准。
- 页面实现以 `03 页面开发手册` 为准。
- 开发顺序以 `06 开发计划与任务拆分` 和本协作包为准。
- 任何冲突都不能通过增加后台、社区或复杂登录解决。
