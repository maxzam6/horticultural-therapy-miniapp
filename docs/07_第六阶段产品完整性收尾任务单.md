## 5. C010 数据与展示口径冻结

### 5.1 路由与导航

```text
P11 → P12：ROUTES.RECORDS，Tab 导航
P12 → P11：recordId
P12 → P13：ROUTES.MINE，Tab 导航
P13 → P12：ROUTES.RECORDS，Tab 导航
P14：Tab 直接进入，不接收业务参数
```

- P12 历史卡片点击后，只携带 `recordId` 进入 P11。
- `recordId` 写入时使用 `encodeURIComponent`，P11 继续使用既有解码逻辑。
- 不新增、删除或重命名路由。

### 5.2 Record 数据来源

- P12 只通过 `experienceStore.loadRecords()` 读取 Record。
- P13 如需成长汇总，读取 Store 的统一汇总结果，不直接读取 Mock、Adapter 或 Storage。
- Record 按 `completedAt` 倒序展示。
- P11、P12 必须引用同一个 Record 对象和 `recordId`；P12 不复制或补写 Record。

### 5.3 成长汇总契约

统一使用：

```js
{
  completedCount,
  exploredSenseCount,
  totalMinutes,
  level
}
```

聚合规则：

- `completedCount`：Record 数量。
- `exploredSenseCount`：Record 中非空 `sense` 去重后的数量。
- `totalMinutes`：所有有效 `duration` 的数值合计；无效值按 0 处理。
- `level`：仅按 `completedCount` 计算。

成长等级沿用 PRD 既定规则：

```text
0 次：等待启程
1 次：初识自然
2–3 次：自然探索者
4–5 次：五感漫游者
6 次以上：自然同行者
```

成长规则只在一个纯 Service 或 Store 统一实现；P12、P13 页面不得各自复制判断公式。已有 Record 内的 `growthIdentity` 只用于历史展示兼容，不作为当前汇总等级的唯一来源。

### 5.4 P13 数据来源

- 用户信息：`userStore.loadCurrentUser()` 与 `userStore.user`。
- 成长身份：第 5.3 节统一成长汇总的 `level`。
- 最近评估：`assessmentStore.loadLatestResult()` 与 `assessmentStore.result`。
- 最近评估只展示 `experienceOverviewScore`、emotion、stress、nature 的已有结果；无结果时显示友好默认状态。
- 页面不得重新评分，不得产生 `balanceIndex`，不得暗示医学诊断或正式量表。
- “关于园艺疗法”和“隐私说明”使用明确的展示版静态文案；不虚构甲方已经审核。

### 5.5 P14 展示边界

- 标题：自然分享空间。
- 正文：自然分享空间，未来开放。
- 可使用统一自然插画或植物装饰。
- 不显示开发状态、内部任务编号、假输入框或不可用社交按钮。
